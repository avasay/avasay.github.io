Blazor Form Validation Part 4: How to Validate Only on Submit

Alejandrio Vasay • October 20, 2025

Stop Blazor form validation on every field change! Learn how to validate only on submit for better UX. Step-by-step guide with code examples.

Introduction

Blazor's built-in form validation is powerful, but it comes with a significant usability issue: it validates as users type. While real-time validation might seem helpful, it creates a frustrating user experience. Imagine filling out a form and seeing error messages appear immediately as you type—before you've even finished entering your information. This "intrusive" validation behavior is the default in Blazor, and many developers struggle to find a better approach.

This tutorial demonstrates how to implement a Blazor form that validates only when the user clicks Submit, provides a much better user experience, and includes a complete flow from client-side validation through to server submission.

The Problem: Intrusive Per-Field Validation

Blazor's default EditForm with <DataAnnotationsValidator /> validates fields continuously:

  • While typing: Error messages appear before you finish entering data

  • On focus change: Switching fields triggers validation immediately

  • Poor UX: Users see errors for incomplete information they're still working on

This approach works against natural form-filling behavior. Users want to complete the form at their own pace and see validation feedback only when they're ready to submit.

The Challenge: Common Mistakes When Implementing "Validate On Submit"

Many developers (including myself!) encounter these pitfalls when trying to disable real-time validation:

Mistake #1: Using OnValidSubmit and OnInvalidSubmit

Why it fails: These handlers automatically validate the form before calling your methods. You don't control when validation happens—Blazor does it for you.

Mistake #2: Always Including <DataAnnotationsValidator />

Why it fails: <DataAnnotationsValidator /> hooks into the EditContext and runs validation automatically on field changes, defeating your "validate on submit" goal.

Mistake #3: The Model Reset Issue

Why it fails: Creating a new model instance without recreating the EditContext causes a mismatch. The validation system evaluates the empty model and displays errors even though submission succeeded.

Mistake #4: Using FormName Attribute (Blazor 8+)

Why it fails: In Blazor Server/.NET 8+, FormName enables Enhanced Navigation and SSR features that can trigger server-side submission before client-side validation completes.

The Solution: Manual Validation with Full Control

The key to "validate only on submit" is taking complete control of the validation process:

1. ✅ Use OnSubmit instead of OnValidSubmit/OnInvalidSubmit

2. ✅ Skip <DataAnnotationsValidator /> entirely

3. ✅ Use ValidationMessageStore for manual error management

4. ✅ Validate manually with Validator.TryValidateObject

5. ✅ Suppress validation until first submit attempt

6. ✅ Recreate EditContext when resetting the form

Validation Rules Explained

The ContactFormModel enforces strict validation:

  • Full Name: Required, 2-100 characters

  • Email: Required, must match email format (user@domain.com)

  • Phone: Required, must match format (123) 456-7890 or variations

  • Message: Required, 10-1000 characters

All four fields must pass validation before the form can submit to the server. This ensures your API receives only clean, valid data.

Conclusion

Blazor's default real-time validation creates a poor user experience, but with the right approach, you can build forms that validate only when users are ready—at submit time. The key is bypassing Blazor's automatic validation system and implementing manual validation with full control.

This approach:

  • Provides a better user experience (no intrusive errors while typing)

  • Validates comprehensively before submission

  • Prevents invalid data from reaching your server

  • Handles the complete flow from client validation to server submission

  • Includes proper error handling and user feedback

The pattern shown here works for any Blazor form, whether it's a simple contact form or a complex multi-step wizard. By taking control of validation timing, you create forms that feel natural and respectful of the user's workflow.
