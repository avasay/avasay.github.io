Blazor Form Validation Part 1: Using DataAnnotations for Simple Forms

Alejandrio VasayOctober 5, 2025

So, you're building a form in Blazor and need to make sure users fill it out correctly. Where do you start? The easiest and most common way is by using DataAnnotations – a set of built-in .NET attributes that let you define validation rules right on your model's properties.

In this step-by-step guide, we'll build a simple "Contact Us" form and see how to use Blazor's built-in components to add validation instantly.

What We'll Build

By the end of this tutorial, you will have a "Contact Us" form that:

  • Validates that the Name and Email fields are not empty.

  • Checks that the Email field contains a valid email address.

  • Ensures the Message is between 10 and 250 characters.

  • Displays clear validation messages to the user.

Step 1: Create the Model Class

First, we need a model class to represent the form data. Create a new class in your project, for example, ContactModel.cs.

Let's break down the validation attributes we used:

  • [Required]: This field must contain a value; it cannot be null or empty.

  • [EmailAddress]: The string must be in a valid email address format.

  • [StringLength]: Defines a maximum and optional minimum length for a string.

> Other Useful DataAnnotations:

>

> - [Range]: Validates that a number is within a specified range (e.g., [Range(1, 120)]).

> - [RegularExpression]: Validates that the data matches a specified regular expression pattern (e.g., for a phone number).

> - [Compare]: Validates that two properties in a model match (e.g., Email and ConfirmEmail).

Step 2: Build the Blazor UI Component

Now, let's create the Blazor component (a .razor file) that will render our form. The key to making Blazor's built-in validation work are two components: <DataAnnotationsValidator /> and <ValidationSummary />.

Understanding the Key Pieces:

1. <EditForm>: This is Blazor's wrapper for a form. It provides context for the validation system.

  • Model="@contactModel": This tells the form which model object to validate against.

  • OnValidSubmit="@HandleValidSubmit": This event callback is triggered only when the user submits the form and all validation rules pass.

2. <DataAnnotationsValidator />: This is the magic component. It hooks the EditForm into the DataAnnotations validation system. Without this, your [Required] and other attributes will be ignored.

3. <ValidationSummary />: This component displays all validation error messages in a single list, typically at the top of the form. It's great for giving users a high-level overview of what needs to be fixed.

4. <InputText> & <InputTextArea>: These are Blazor's built-in input components. Unlike a standard HTML <input>, they are designed to work with the EditForm and validation system. They automatically apply CSS classes to show validation state (e.g., valid or invalid).

Step 3: Run and Test

Run your application and navigate to the /contact page. Try the following:

1. Click "Submit" with all fields empty. You'll see all the "required" error messages in the summary.

2. Fill in a name and an invalid email (like "not-an-email"). You'll see the email error.

3. Write a message that is only 5 characters long. You'll see the StringLength error.

4. Finally, correct all errors. When you submit, the HandleValidSubmit method will run, and the console will log your success message.

Conclusion

And there you have it! You've successfully set up a fully validated form in Blazor using DataAnnotations. The process is straightforward:

1. Decorate your model with validation attributes.

2. Wrap your form in an <EditForm>.

3. Include the <DataAnnotationsValidator /> and either a <ValidationSummary /> or individual <ValidationMessage /> components.

This provides a robust, client-side-like validation experience that runs on the server (or WebAssembly) and is the foundation for all more advanced validation scenarios in Blazor.
