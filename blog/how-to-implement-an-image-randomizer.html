How to Implement Image Randomizer Web API

Alejandrio VasayNovember 13, 2025

Introduction

In this tutorial, we'll build a Web API that serves random images from a directory. This is perfect for scenarios like rotating hero banners, random profile pictures, or dynamic background images. Along the way, we'll learn about ASP.NET Core Web APIs, in-memory caching for performance optimization, and proper random number generation.

What we'll build: An API endpoint that returns a random image from a specified directory, with caching to improve performance.

What you'll learn:

  • Creating a Web API controller in ASP.NET Core

  • Using IMemoryCache for caching

  • Thread-safe random number generation with Random.Shared

  • Dependency injection in ASP.NET Core

  • Returning file responses from APIs

Prerequisites

  • .NET 6 SDK or later

  • A code editor (Visual Studio, VS Code, or Rider)

  • Basic knowledge of C# and REST APIs

Why Cache the File List?

Scanning directories is expensive. By caching the file list for 10 minutes:

  • We avoid repeated disk I/O operations

  • The API responds faster on subsequent requests

  • We still refresh the cache periodically to detect new images

Random.Shared vs new Random()

Random.Shared (introduced in .NET 6) is:

  • Thread-safe

  • More performant than creating new instances

  • Prevents issues with rapid successive calls returning the same "random" number

Understanding the Flow

Let's trace what happens when a request comes in:

  1. Request arrives: GET /api/BannerRandomizer?path=/images/banners/home-page/

  2. Controller receives request: The BannerRandomizerController is instantiated with its dependencies injected

  3. Directory processing:

    • DirectoryCacher checks if the file list for this directory is cached

    • If not cached: Scans the directory, filters for image files, caches the list for 10 minutes

    • If cached: Uses the cached list

    • Picks a random file from the list using Random.Shared

  4. Image loading:

    • ImageCacher checks if this specific image is cached

    • If not cached: Reads the image bytes from disk, wraps in ImageObject, caches indefinitely

    • If cached: Returns the cached bytes

  5. Response: Controller returns the image bytes with the appropriate content type

Common Issues and Solutions

Issue: "Directory not found" errors

Solution: Ensure your images are in the wwwroot folder and the path is correct.

Issue: Same image keeps appearing

Solution: Check that you're using Random.Shared instead of creating new Random() instances repeatedly.

Issue: High memory usage

Solution: Implement cache size limits and consider storing file paths instead of byte arrays for large images.

Issue: Images not updating after adding new files

Solution: The file list cache expires after 10 minutes. Lower this value or implement a cache-clearing endpoint.

Conclusion

You've built a production-ready image randomizer API with proper caching and modern .NET practices. The key takeaways:

  • ASP.NET Core Web APIs provide a clean way to build HTTP services

  • IMemoryCache dramatically improves performance for read-heavy operations

  • Random.Shared provides thread-safe, efficient random number generation

  • Dependency Injection makes your code testable and maintainable

This pattern can be adapted for many scenarios beyond images—any time you need to serve random content from a collection with good performance.
