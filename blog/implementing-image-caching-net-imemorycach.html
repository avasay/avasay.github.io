Implementing Image Caching in .NET: IMemoryCache Tutorial

Alejandrio VasayDecember 11, 2025

Loading images from disk repeatedly can be a performance bottleneck in your applications. Whether you're building a web API, a console application, or a desktop app, caching images in memory can dramatically improve response times and reduce I/O operations.

In this tutorial, I'll show you how to implement efficient image caching using IMemoryCache in .NET. We'll build a complete console application called ImageCacher that demonstrates all the key concepts you need to know.

Why IMemoryCache?

Before we dive into the code, let's talk about why IMemoryCache is a great choice for caching:

Works Everywhere: Despite being in the Microsoft.Extensions.Caching.Memory namespace, IMemoryCache isn't ASP.NET-specific. It works in any .NET application type including console apps, web apps, Web APIs, Windows Services, Worker Services, and desktop applications (WPF, WinForms, MAUI).

Built-in and Reliable: It's part of the core .NET libraries, well-tested, and requires minimal setup.

Automatic Memory Management: It handles cache eviction based on size limits, expiration policies, and memory pressure, so you don't have to worry about memory leaks.

Fast: In-memory caching provides near-instant access to cached data compared to disk I/O.

Key Features Explained

Cache Options: We configure the cache with both sliding and absolute expiration. Sliding expiration (30 minutes) resets each time the item is accessed, while absolute expiration (2 hours) ensures items are eventually removed regardless of access patterns.

GetOrCacheImageAsync: This method implements the "get or create" pattern. It first checks if the image is in cache, and only loads from disk if it's not found. This is the most common pattern you'll use.

Size-Based Eviction: By setting a size for each cache entry, we can limit the total number of cached items, preventing unbounded memory growth.

Async File Operations: We use ReadAllBytesAsync to avoid blocking threads during I/O operations.

Content Type Detection: The GetContentType method automatically determines the MIME type based on the file extension.

Important Considerations

Memory Usage: Each cached image consumes memory. For large images or many cached items, monitor your application's memory usage and adjust the cache size limit accordingly.

In-Process Only: IMemoryCache stores data in the application's process memory. If you're running multiple instances of your application (load-balanced web servers, for example), each instance will have its own separate cache. For distributed scenarios, consider using IDistributedCache with Redis or SQL Server.

Cache Invalidation: The current implementation uses time-based expiration. If images can be updated on disk, you might want to implement cache invalidation based on file modification dates or add a manual refresh mechanism.

Thread Safety: IMemoryCache is thread-safe, so you can safely use it from multiple threads without additional synchronization.

Conclusion

Image caching with IMemoryCache is a powerful technique that works across all .NET application types. The ImageCacher service we built provides a clean, reusable abstraction that handles loading, caching, and retrieving images efficiently.

The key takeaways are that IMemoryCache is lightweight, works everywhere in .NET, automatically manages memory, and provides significant performance improvements for frequently accessed images. Whether you're building a console app, web API, or desktop application, this pattern will serve you well.

The complete source code from this tutorial can be adapted to cache other types of files or data as well.
